# Day 1：亲手完成 React 对话界面

## 今天必须理解

- 变量、函数、数组和对象分别解决什么问题。
- `async/await` 为什么不会让网络请求立即得到结果。
- TypeScript 的类型如何提前发现错误。
- React 组件、属性和状态的区别。
- 表单提交后，为什么要阻止浏览器刷新页面。

## 练习顺序

1. 不看答案，创建 `ChatMessage` 类型：角色只能是 `user` 或 `assistant`，并包含唯一标识、文本和创建时间。
2. 创建 `ChatMessageList` 组件，把消息数组显示出来。
3. 创建输入组件，禁止提交纯空格。
4. 提交后立即显示用户消息，并清空输入框。
5. 用一个延迟函数模拟 Agent，两秒后添加助手回复。
6. 增加发送中状态和错误提示。
7. 在窄屏浏览器中检查页面能否使用。

## 完成标准

- 不依赖 AI，从空白文件重新写出消息类型和表单提交逻辑。
- 能解释 `map`、`useState`、事件处理和异步等待。
- 刷新页面不会出现控制台错误。
- 为“空消息不能发送”和“用户消息正常出现”各写一个测试。

## 使用 Codex 的方式

先自己写 30–45 分钟。卡住时只询问错误原因或要求一个更小的示例，不请求完整页面。完成后让 Codex 做代码审查和出追问题。
